# 已知坑与修法（实战沉淀）

> 本次 22 页国网汇报 PPT 迭代中真实踩过的坑。每条按「症状 → 根因 → 修法」组织。

## 1. 旧 CSS 全局短类名污染新结构 ⚠️ 最高频

- **症状**：新加的卡片子元素全部堆在卡片左上角，或直接消失不显示。
- **根因**：页面旧 `<style>` 里定义过全局短类规则（`.k{position:absolute}`、`.bk{position:absolute}`、`.lg`、`.n-sub{display:none}`），特异性或位置压过新规则。
- **修法**：新结构类名一律带页面前缀（`.p17-kpi .k`、`.p20-cols .bk`），并显式覆盖 `position:static !important` / 改名避开。**预防：写新结构前先 grep 该页旧 CSS 是否已有同名类。**

## 2. 文本替换 MISS（字符串被标签拆开）

- **症状**：`str.replace` 报告改了但页面没变，或找不到目标串。
- **根因**：正文里 `<br>`、`<b>` 把一句话拆成多个文本节点，Python 全文替换匹配不到完整句子。
- **修法**：先 Read 该页确认原文的标签切分方式，按行/按片段分别替换；改完 grep 验证新旧串。

## 3. 图片与框比例不符

- **症状**：图塞进卡后大片留白或溢出。
- **修法**：a) CSS 层 `height:100%;width:auto;object-fit:contain`；b) 比例差太大（>30%）时先用 Pillow 按目标比例裁剪图片再嵌入（白边裁剪、保留核心区）。图片内文字溢出是同样问题——裁剪或重绘，不要靠缩放硬塞。

## 4. nowrap 文字溢出（QA FAIL: "nowrap text overflow"）

- **症状**：QA 报 `sw>cw`，如「趋势不准 sw48>cw42」。
- **修法**：加宽所在列/容器（42→52px），或去掉 `white-space:nowrap`。中文两字词最小安全列宽 ~52px。

## 5. 旧规则特异性压过新规则

- **症状**：改了 margin/position 不生效。
- **根因**：旧 CSS 有更高特异性的组合选择器（如 `.belt .bbody`）。
- **修法**：新规则用同样（或更高）的特异性前缀重写，如 `.belt .bbody{...}`，而不是裸 `.bbody`。

## 6. QA 通过标准

- 预期结果：`status: WARN`（仅 "PNG size 1280x720" 与 "PNG very busy" 两条 WARN 属正常），**不允许任何 `[FAIL]`**。
- QA 命令：`python visual_qa_local.py <png> <planningN.json> <slide-N.html> <out.txt>`
- 视觉终检仍需人工看图：QA 查不出「布局语义混乱」「信息密度不均」这类问题。

## 7. Windows 编码

- 所有 Python 脚本输出中文前加：`sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")`
- 或运行时 `PYTHONIOENCODING=utf-8`。GBK 控制台直接 print emoji/中文会 UnicodeEncodeError。

## 8. PPTX 结构假设

- 组包脚本假设每页恰好 1 张满屏 picture（ppt-agent presentation-png 管线产物）。若页数与 png-hi 文件数不一致会漏页——先核对 `len(prs.slides)` 与 PNG 数量。
- 每次重建前自动做 `.bak.pptx` 备份；回读校验 sha1 + 3840×2160 + 满屏。

## 9. 交互纪律（用户强约束，来自本项目）

- **只改用户明确要求的，没说的不要动**——这句是用户的原话约束，改前复述范围、改后逐条汇报。
- 并发 subagent 上限 2 个（用户环境约束）。
- 框与内容自适应问题的用户偏好：**「框不变，内容在框内匀开」**。

## 10. 导语条上方像"空一行"（padding-top 过大）

- **症状**：用户反馈"导语文字上面有一行空格"；文字被压到框底部。
- **根因**：`.tpl-lede{padding-top:31px}` 之类的大内边距，把文字推到框底（3 行时下方只剩 1px）。
- **修法**：把 `padding-top` 调到 ~16px（两行/三行都适用），使上留白约 18px、上下相近。QA 已内置 `lede spacing` 检查，上留白 ≥28px 或上下差 ≥12px 会 WARN。

## 11. 数字烘焙在图片里

- **症状**：改了页面文字，图里还是旧数字（如页面 76%、图里 88%）。
- **做法**：能溯源到绘图脚本的（fig2-1/3-1/3-2/4-2/5-7 等）回脚本改字重出图；外部导出图（如 fig4-1）用 `scripts/patch_png_text.py` 原位替换，先 `--probe` 找行带，再按 `--box/--text/--size` 重绘，自动留 `.bak.png`。
- **注意**：同一数字常同时出现在导语、卡片、图、表里，改完 `grep` 全页核对。

## 12. 页码与章节号是图片内容

- **症状**：删页后出现 `08/22 → 09/21 → 11/22` 跳号。
- **修法**：`scripts/delete_slide.py` 负责删 PPTX 页、文件前移、页码重排；章节号（2.1.4→2.1.3）与交叉引用手工改；TOC 若只列大章则无需改。改完重渲染 1x/3x 并重新组包。

## 13. 口径一致性（最容易翻车）

- 真实踩过：页面写「六组平均 79.0%→79.9%」，实验数据实为 79.81%→80.94%；图里 88% 与页面 76% 冲突；98.32% 与 98% 同值不同写法。
- **做法**：以实验 JSON / 报告表格为唯一源，逐项核对；同一数字在多处出现时全部核对；拿不准就先问用户，不凭印象写。

## 14. 数字与单位的写法

- 不要写 `pp`：绝对差写「个百分点」（或按用户偏好直接写 `%`），相对变化才写「%」。
- 斜杠并列的数字要在文字里标明各是谁（如「工作日、周末准确率分别为 A、B」），避免读者对位困难。

## 15. PPTX 被占用 / 用户看到旧版本

- `PermissionError: ... .pptx` → 文件被 PowerPoint/WPS 占用，请用户关闭后重试。
- 用户坚持"打开还是旧的"：先 `deck_audit.py` 校验页码与图片哈希；再解压 PPTX 读 `presentation.xml` 的 `sldIdLst` 与 `media` 哈希佐证；最后另存新文件名让用户打开，排除缓存/打开的是备份。

## 16. 调整曲线数据的展示口径

- 用户要求整体抬升准确率时：**保持相对差距不变**（两边同加），曲线用滚动平均平滑、深谷压缩，避免"断崖式"下跌；参数（如 OFFSET / DIP_SHRINK）留在脚本里，便于回退。
- 图改了，页面上的绝对数值（卡片、KPI）必须同步改。

## 17. 措辞类修改先给草稿

- 用户习惯：先看文字（常要求给 2 个版本选），确认后再动 PPT。改稿时先输出草稿并标出改动点，不要直接改文件。
